# 정치경제 스프링제본 교재 — 코드 재설계용 정리물

이 폴더는 지금까지 대화에서 정리·합의된 내용을 코드(HTML/CSS 기반)로 처음부터 다시
디자인할 때 바로 쓸 수 있도록 정리한 것입니다. 원본 PDF를 직접 패치하는 방식은
여기서 멈추고, 이 폴더의 데이터를 입력으로 삼아 새로 레이아웃을 짜면 됩니다.

## 1. 프로젝트 개요

- 원본 자료: `정경.pdf` (표지연 선생님, TIS 종과 기초반 교재) — 정치(파트1) / 경제(파트2) /
  지리(파트3) 세 파트로 구성.
- 이번 작업 범위: **파트1(정치) + 파트2(경제)만** 새로 디자인. 지리(파트3)는 제외.
- 용도: 스프링(코일) 제본. A4 용지, 제본 여백(왼쪽) 확보 필요.
- 표지: 기존 파일 `cover.pdf` 그대로 사용 — 새로 디자인하지 않음.
- 목차: 새로 생성 (본 폴더에 이미 완성된 디자인이 있음, 아래 3번 참고).
- 본문에는 원문 검토 과정에서 확정된 80건의 오탈자/사실관계 수정사항이 **이미 반영된
  상태**로 `content.json`에 들어 있음 (아래 4번 참고). 즉 content.json의 텍스트가
  최종 교정본이며, 추가로 원본 PDF의 오류 텍스트를 다시 참고할 필요는 없음.

## 2. 폰트

- Noto Sans CJK KR을 사용.
- 본문(얇은 글씨): `fonts/Thin.otf`
- 제목/강조(굵은 글씨): `fonts/Bold.otf`
- 원본 PDF에서 실제로 쓰인 두 굵기만 추려서 넣었음. 사용자가 업로드했던 9개 굵기
  파일(Black/Bold/DemiLight/Light/Medium/Regular/Thin 등) 중 필요하면 더 쓸 수 있음 —
  본문·소제목 전부 이 두 굵기로 충분히 표현됨.

## 3. 목차(TOC) 디자인 — 확정됨, 사용자 승인 완료

레이아웃은 승인받았고, 아래 규칙 그대로 재구현하면 됩니다.

- 2단 구성 유지. 컬럼 사이 간격은 넉넉하게 (원본 시도에서 34pt 정도가 "너무 좁지
  않다"는 평가를 받음 — 절대값보다는 "여유 있게"가 핵심 피드백).
- 페이지 여백도 넉넉하게: 촘촘한 첫 버전(폰트 작음·여백 없음·간격 좁음)은 반려됨.
  두 번째 버전(폰트 키우고 여백·간격 확대)이 승인됨.
- 계층 구조 3단계:
  1. **파트 제목** (예: "파트 1 : 정치") — 굵게, 큼직하게(17pt 선), 포인트 컬러
     (주황, RGB 약 0.80/0.36/0.09 ≈ `#CC5C17`), 밑줄 룰(rule) 한 줄.
     → **주황색은 목차에서는 OK** (사용자가 목차 디자인 자체는 마음에 들어함).
     본문에서는 주황 금지 (아래 6번 참고).
  2. **대단원(L1)** — 굵게, 검정, 12pt 선. **번호를 붙이지 않음**: 원본에서 "1, 2, 3…"
     번호가 여러 하위 그룹마다 로컬하게 다시 시작되는 구조라, 목차에 그대로 나열하면
     번호가 자꾸 1로 리셋되는 것처럼 보여 혼란스러웠음 → 숫자를 떼고 제목만 굵게 표시.
     점선 리더(dot leader) + 페이지 번호.
  3. **소제목(SQ)** — 얇은 글씨, 회색, 9.8pt 선, 들여쓰기. 점선 리더 + 페이지 번호.
     원본에서 정치 파트는 "■", 경제 파트는 "●"를 소제목 기호로 썼는데 **둘 다 같은
     레벨로 취급**해야 함 (안 그러면 경제 파트 소제목이 정치 파트보다 훨씬 부실해
     보임 — 실제로 이 문제가 있었고 수정함).
- 페이지 번호 오프셋: 표지(1p) + 목차(N p) 다음부터 본문 페이지 번호가 시작.
  최종 확정본에서는 목차가 5페이지였음 (표지=1, 목차=2~6, 본문=7~57).
  → 코드 재설계에서는 페이지 수가 달라질 수 있으니 이 숫자 자체보다는 "표지 다음
  목차, 목차 다음 본문"이라는 순서 규칙만 유지하면 됨.
- 참고: 원본 문서의 뒷부분(사회보장 후반부~국제사회/UN 단원, 대략 원본 페이지
  43~51)은 소제목 표기 방식이 원문자(①②③)나 마침표 붙은 번호 등으로 뒤섞여 있어
  자동 추출이 부정확했음. 목차에서는 이 구간이 대단원 정도만 보이고 소제목이
  성기게 나옴 — 사용자가 "이 정도면 괜찮다"고 확인함. 코드 재설계 시 원한다면
  `content.json`의 해당 페이지(43~51) 텍스트를 손으로 다듬어 소제목을 보강할 수 있음.

## 4. content.json — 본문 텍스트 (구조화됨, 교정 완료)

`content.json`은 `{"pages": [...]}` 형태이며, 각 페이지는:

```json
{
  "page": 1,
  "blocks": [
    {"items": [
      {"marker": "PART", "symbol": null, "text": "파트1 : 정치"}
    ]},
    {"items": [
      {"marker": "L1", "symbol": null, "text": "1 정치 사회의 특성"},
      {"marker": "H1", "symbol": "■", "text": "투쟁 사회와 정치"},
      {"marker": "H2", "symbol": "◯", "text": "사회적 동물로서의 인간"},
      {"marker": "TEXT", "symbol": null, "text": "인간은 집단(가족) 속에서 태어나고..."}
    ]}
  ]
}
```

- `page`: 원본(정경.pdf) 기준 1~51 페이지 번호. 1~23이 파트1(정치), 24~51이 파트2(경제).
- `blocks`: PDF에서 시각적으로 한 덩어리로 잡힌 텍스트 박스 단위(대략 문단 단위).
- `items`: 그 블록 안의 줄들을 순서대로 분류한 것. `marker` 종류:
  - `PART` — 파트 제목 ("파트1 : 정치", "파트2 : 경제") — 페이지 1, 24에만 등장.
  - `L1` — 대단원 제목. 원본 그대로 앞에 번호가 붙어 있음 (예: "1 정치 사회의
    특성") — 이 번호가 로컬하게 리셋되는 문제가 있으므로, 화면에 쓸 때는 앞의
    숫자를 떼고 쓰는 걸 추천 (목차에서 이미 그렇게 처리함).
  - `H1` — "■" 또는 "●"로 시작하던 소제목. `symbol` 필드에 원래 어떤 기호였는지
    들어있음 (정치 파트는 대부분 ■, 경제 파트는 대부분 ●— 같은 레벨로 취급할 것).
  - `H2` — "◯"/"〇"/"○" (세 가지 원 문자가 혼용됨, 전부 같은 레벨) 로 시작하던
    한 단계 더 세부적인 소제목.
  - `H3` — "◎"로 시작하는 항목 (일부 페이지, 국회 관련 단원 등에서만 등장, 14건).
  - `NOTE` — "※" 또는 "＊"로 시작하는 보충설명/주석 줄.
  - `TOPIC` — "TOPIC :" 형태로 시작하는 박스 (7건, 심화/읽을거리 코너).
  - `TEXT` — 본문 문단. 같은 블록 안에서 연속된 TEXT 줄은 이미 하나의 문단으로
    합쳐놓았음 (줄바꿈은 공백으로 치환).
- 소제목 한 줄에 기호가 두 번 이상 들어있던 경우(예: "●1929년 세계 대공황 ●뉴딜
  정책(New Deal)")는 이미 두 개의 별도 H1 항목으로 분리해뒀음.
- **콜론 규칙(본문 스타일링 힌트)**: H1 항목 중 `text`에 콜론(":")이 있는 경우
  (예: "소비에트 사회주의의 구조 : 생산수단의 사회적 소유"), 원래 PDF 패치 버전에서는
  콜론 앞부분만 굵게 하고 뒤는 일반 굵기로 뒀음 (콜론 뒤가 사실상 본문 설명 문장이라
  통째로 굵게 하면 눈에 부담됨). 코드로 재설계할 때도 이 규칙을 유지하는 걸 추천.

## 5. images/ + images.json — 그림·도표·사진

원본 PDF에 래스터(비트맵) 이미지로 박혀 있던 다이어그램·차트·사진 33개를 최고 품질로
추출했음 (`images/page{NN}_img{k}.png`).

`images.json`은 각 이미지에 대해:
- `page`: 몇 페이지 소속인지 (content.json의 page 번호와 동일 기준)
- `file`: 파일명
- `px_w`/`px_h`: 픽셀 크기 (원본 해상도 그대로, 리사이즈 안 함)
- `rect_pt`: 원본 PDF에서 이 이미지가 차지하던 좌표 (pt 단위, [x0,y0,x1,y1])
- `page_w_pt`/`page_h_pt`: 그 페이지 전체 크기 (참고용 비율 계산에 씀)
- `column`: `rect_pt`의 x0가 페이지 절반보다 왼쪽/오른쪽인지로 추정한 "왼쪽 컬럼 /
  오른쪽 컬럼" 힌트. 원본이 2단 레이아웃이라 이미지도 대부분 한쪽 컬럼 폭에 맞춰
  들어가 있었음.

### 주의: 이미지로 안 잡히는 표(테이블)

원본에는 이미지가 아니라 **벡터로 직접 그린 표**가 여러 페이지에 있음 (선·칸을
도형으로 그리고 그 위에 텍스트를 올린 방식 — 예: 사회보장 급여 비교표, 국가별
세금부담률 표 등). 이런 표는 `images/`에 없고, 표 안의 텍스트 자체는
`content.json`의 TEXT 항목으로는 들어가 있지만 표의 행/열 구조 정보는 없음.
아래 페이지들은 벡터 드로잉이 많아(표일 가능성이 높음) 수동으로 HTML `<table>`을
다시 짜야 할 수 있음:

```
3, 5, 15, 18, 20, 21, 22, 23, 24, 26, 30, 31, 33, 37, 40, 44, 45, 46, 47, 48, 49, 50
```

(원본 PDF를 열어서 해당 페이지를 눈으로 보고 표 구조를 확인 후 재구성 추천.)

## 6. 본문 헤더 스타일링 규칙 (PDF 패치 버전에서 실제로 적용했던 규칙)

원본 PDF를 직접 패치할 때 아래 순서로 시행착오를 거쳐 확정된 규칙입니다. 새 코드
버전에서도 그대로 따르면 무난합니다.

1. **주황색 쓰지 않음.** 처음엔 목차와 통일감을 주려고 본문 소제목도 주황색으로
   칠했는데, "눈이 너무 아프다"는 피드백을 받고 검정 볼드로 전부 바꿈. → 본문은
   H1/H2/L1 전부 **검정 + 볼드**만 사용.
2. **파트 제목("파트1 : 정치")은 건드리지 않음.** 원본에 이미 자체 회색 강조박스 +
   굵은 글씨로 디자인되어 있었음. 여기에 흰 배경을 깔고 다시 칠했더니 회색 박스가
   사라져 보여서 "이상해졌다"는 피드백을 받음 → 파트 제목은 원본 그대로 완전히
   손대지 않는 게 정답. 코드로 새로 만들 때도 파트 제목 배너는 (원본처럼) 옅은
   회색 배경 박스 + 굵은 글씨 정도로 별도 디자인하면 됨. 주황색을 쓸지, 원본처럼
   회색을 쓸지는 자유롭게 새로 정해도 됨 — 이 항목만은 "새로 디자인 가능" 영역.
3. **콜론 규칙.** H1(■/●) 줄인데 콜론이 있고 그 뒤로 긴 설명 문장이 붙는 경우
   (예: "프랑스 : 제5공화국 헌법(1958)으로 대통령에게 강한 권한을 부여하고..."),
   콜론까지만 굵게, 나머지는 일반 굵기. 짧은 제목형 H1(콜론 없음, 예: "관리 가격
   (Management Pricing)")은 전체를 굵게.
4. H2(◯)에 대해서는 아직 별도 스타일 규칙을 정하지 않았음 (PDF 패치판에서는
   H1까지만 볼드 처리하고 멈춘 상태). 코드 재설계 시 H1보다 살짝 약한 강조(예:
   세미볼드, 또는 볼드는 유지하되 크기만 살짝 작게)를 주는 걸 추천하되, 이 부분은
   아직 사용자 확인을 받지 않았으니 시안을 보여주고 확인받는 게 좋음.

## 7. 페이지/제본 관련 참고 수치 (PDF 패치판 기준, 강제 아님)

남겨둠:

- 용지: A4 (595.28 × 841.89 pt)
- 원본 2단 본문을 88% 스케일로 축소해서 배치
- 왼쪽(제본) 여백 약 20mm(56.7pt), 오른쪽 약 5mm, 위/아래 각각 약 17.8mm
- 하단 중앙에 작은 페이지 번호(9pt, Thin, 회색)
